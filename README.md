# XKeen Resist Watcher

[![Test](https://github.com/DalasDV/xkeen-resist-watcher/actions/workflows/test.yml/badge.svg)](https://github.com/DalasDV/xkeen-resist-watcher/actions/workflows/test.yml)

На основе [xkeen-subscription-watcher](https://github.com/tkukushkin/xkeen-subscription-watcher).

## Отличия форка

XKeen Resist Watcher — самостоятельный форк. Помимо импорта подписок по
ссылкам, он читает Xray JSON из Remnawave, пропускает профили с готовыми
балансировщиками и сохраняет имена нод и параметры их подключений. Запросы
подписки отправляют аппаратный HWID, когда роутер предоставляет данные для
его вычисления. У форка свой установщик из публичных релизов GitHub и мастер
с резервным копированием Xray, расписанием обновлений и выбором режима.

## Использование

```bash
xkeen-subscription-watcher <tag>=<url>
```

Можно передать несколько пар `<tag>=<url>`

Скрипт получает из переданных подписок прокси, генерирует конфиги `04_outbounds.<tag>.json`.

Если конфиги изменились, выполняется `xkeen -restart`.

### Xray JSON из Remnawave

Watcher автоматически распознаёт массив профилей Xray или один объект с
`outbounds`. Он переносит серверные выходы со всеми вложенными параметрами,
префиксует их теги именем подписки и по возможности использует `remarks` как
имя сервера. DNS, inbounds, routing и служебные выходы профиля остаются на
стороне подписки. Если серверный выход ссылается на другие выходы по тегу,
эти ссылки должны разрешаться в конфигурации роутера.

Для Remnawave добавьте правило выдачи `XRAY_JSON` по User-Agent
`XKeen-Subscription-Watcher` выше общего fallback. Выдача списков ссылок и
Base64 также поддерживается. Для `hysteria2://` и `hy2://` доступны SNI,
пин сертификата, ECH, Salamander/Gecko и диапазоны портов. Версия ядра Xray
определяет, какие поля оно сможет применить. Пустой или некорректный ответ
не заменяет существующий файл.

### Поддерживаемые протоколы

- `vless` (reality / tls / none; транспорты `tcp`, `raw`, `ws`, `grpc`, `xhttp`)
- `vmess` (формат `vmess://base64(JSON)`)
- `trojan`
- `shadowsocks` (`ss`)
- `hysteria2`

Для `vmess` и `trojan` поддерживаются транспорты `tcp`, `raw`, `ws`, `grpc`.
Узлы с транспортами, которые удалены из актуального Xray (`h2`/`http`, `quic`,
`kcp` и т.п.), пропускаются с предупреждением в логе — чтобы один такой узел не
ломал весь конфиг.

### Флаги

- `--output-dir <path>` — каталог для конфигов (по умолчанию `/opt/etc/xray/configs`)
- `--no-restart` — не перезапускать XKeen после обновления
- `--single-proxy` — брать только первый прокси из подписки
- `--protocol-tags` — добавлять к тегам выходов `--hy2`, `--xhttp` или `--other` для отдельных селекторов балансировщика
- `--reality-fingerprint <fp>` — переопределить fingerprint для Reality
- `--dialer-proxies=<proxy1>,<proxy2>` — dialer proxies через запятую

## Установка

Запускайте в оболочке Entware на роутере. Установщик определяет архитектуру,
скачивает сборку из последнего релиза, сверяет SHA-256 и ставит её в
`/opt/sbin/xkeen-subscription-watcher`. При обновлении прежний бинарник,
конфиги Xray и запись расписания можно восстановить из указанной папки
резервной копии. Рабочие файлы выходов обновляет сам watcher при первом
успешном чтении подписки.

### Запуск на роутере

В терминале Entware:

```shell
curl -fsSL https://github.com/DalasDV/xkeen-resist-watcher/releases/latest/download/install.sh \
  -o /tmp/xkeen-resist-install.sh &&
  sh /tmp/xkeen-resist-install.sh
```

### Шаги мастера

1. Запустите установщик в терминале Entware. После скачивания и проверки
   сборки он запустит мастер. Если установщик запущен без терминала, откройте
   мастер командой `/opt/sbin/xkeen-subscription-watcher setup`.
2. Вставьте полную ссылку подписки и нажмите Enter. Пустая строка завершает
   мастер. Для Remnawave используйте правило `XRAY_JSON`, описанное выше.
3. Выберите режим и нажмите Enter.
   - `1` — заменить балансировщики и мониторинг Xray. Мастер настраивает
     `leastPing` и проверку задержки. Если в подписке есть Hysteria и XHTTP,
     Xray сначала выбирает доступную Hysteria по задержке. Когда ни одна
     Hysteria недоступна, он выбирает XHTTP из резервного пула. Прежние имена
     балансировщиков, на которые ссылаются правила, ведут в новый основной пул.
     Существующий `burstObservatory.pingConfig` используется для новых групп.
     Watcher проверяет итоговый конфиг и перезапускает XKeen при изменениях.
   - `2` или Enter — только файл серверов `04_outbounds.<tag>.json`. При
     чистой установке тег — `watcher`. Мастер и последующие обновления в этом
     режиме сохраняют остальные конфиги и не перезапускают XKeen. Если ранее
     использовался автоматический режим, перед ручным перезапуском проверьте
     ссылки на прежний `watcher-to-xhttp` и старые теги серверов.
4. Проверьте вывод мастера. Перед применением он сохраняет все файлы каталога
   Xray в отдельном снимке внутри `/opt/etc/xray/configs/watcher-backup/`.
   Мастер выводит точный путь к копии и сообщает об успешном перезапуске.
   Ссылка и выбранный режим сохраняются в закрытом файле настроек. Мастер
   сохраняет существующее расписание Watcher или добавляет обновление раз в час.

**Политику маршрутизации роутера задаёте вы.** Watcher не решает, какие сайты,
устройства и приложения должны идти через VPN. Чтобы направить нужный трафик
в новый балансировщик, укажите `"balancerTag": "proxy"` в выбранных вами
правилах Xray. Мастер добавляет техническое правило для перехода на резервный
пул и может перенести прямую ссылку со старого тега Watcher на новый, если
конфигурация ноды однозначно совпадает.

Чтобы поменять ссылку или режим, снова запустите `setup`. При переходе со
старой версии без сохранённого режима запустите мастер один раз. Для ручного
обновления сохранённой подписки используйте
`/opt/sbin/xkeen-subscription-watcher refresh`.

### HWID роутера

Watcher отправляет `x-hwid` при загрузке подписки. Он хеширует серийный номер
устройства, а если он недоступен — постоянный MAC физического интерфейса.
При переустановке с тем же аппаратным источником получается тот же HWID.
Если роутер не предоставляет ни одного из этих значений, заголовок опускается.
При включённом лимите устройств роутер занимает собственное место в подписке.
См. [документацию Remnawave](https://docs.rw/features/hwid-device-limit/).


### Crontab

Этот раздел для ручной настройки без мастера.

```shell
crontab -e
```

Добавляем что-то вроде:

```crontab
0 * * * * /opt/sbin/xkeen-subscription-watcher <tag>=<url>
```

### Настройка Xray

Убираем из `04_outbounds.json` прокси, которые будут теперь генерироваться из подписок,
иначе теги будут конфликтовать, оставляем например такое:

```json
{
  "outbounds": [
    {
      "tag": "direct",
      "protocol": "freedom"
    },
    {
      "tag": "block",
      "protocol": "blackhole",
      "response": {
        "type": "HTTP"
      }
    }
  ]
}
```

В `05_routing.json` добавляем конфигурацию `balancers` и `burstObservatory` для автоматического выбора лучшего прокси,
далее в `rules` используем `balancerTag` вместо `outboundTag`, например:

```json
{
  "routing": {
    "domainStrategy": "AsIs",
    "balancers": [
      {
        "tag": "proxy",
        "selector": ["<tag>"],
        "strategy": {
          "type": "leastPing"
        }
      }
    ],
    "rules": [
      {
        "inboundTag": ["socks", "http"],
        "balancerTag": "proxy"
      }
    ]
  },
  "burstObservatory": {
    "subjectSelector": ["<tag>"],
    "pingConfig": {}
  }
}
```

Разово запускаем команду из crontab, проверяем, что всё работает.
